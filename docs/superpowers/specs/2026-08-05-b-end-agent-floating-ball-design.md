## 1. 概述

### 1.1 目标

为 B 端（医院管理/医生工作站）添加 AI 助手悬浮球，提供与 C 端类似的 Agent 交互体验，但功能聚焦于医生诊疗辅助。

### 1.2 背景

C 端前端已实现完整的 Agent 功能（悬浮球 + 聊天面板），支持智能导诊、挂号、问诊、购药等功能。B 端需要类似的 AI 助手，但功能侧重于：
- 病历查询
- 诊断辅助
- 处方审核
- 药品查询

### 1.3 设计原则

1. **纯前端实现**：不改动 Java 后端和 Python Agent 代码
2. **复用现有架构**：复用 C 端的 Agent 组件和服务层
3. **适配 B 端风格**：UI 样式适配 Ant Design 桌面端风格
4. **最小化改动**：只修改必要的配置和样式

```
│  └─────────────┘  └─────────────┘  └─────────────┘         │
│         │                │                │                 │
│         └────────────────┼────────────────┘                 │
│                          │                                  │
│                    ┌─────▼─────┐                            │
│                    │  服务层    │                            │
│                    │ agent.ts  │                            │
│                    └─────┬─────┘                            │
│                          │                                  │
└──────────────────────────┼──────────────────────────────────┘
                           │

              ┌────────────────────────┐
              │   Python Agent (8081)  │
              │   scope: 'b_end'       │
              └────────────────────────┘
```

### 2.2 数据流

```
用户点击悬浮球
    ↓
打开聊天面板
    ↓
用户输入问题
    ↓
前端调用 /api/chat/stream (scope='b_end')
    ↓
Python Agent 处理请求
    ↓
SSE 流式返回响应
    ↓
前端渲染消息、思考过程、工具调用
    ↓
（可选）L2 确认卡片
    ↓
用户确认/取消
    ↓
继续对话或结束
```

### 2.3 认证流程

```
B 端前端
    ↓
从 Sa-Token 获取 JWT
    ↓
添加 Authorization: Bearer <token>
    ↓
调用 Agent API
    ↓
Python Agent 验证 token
    ↓
返回响应（401 时跳转登录页）
```

## 4. 服务层设计

### 4.1 services/agent.ts

**职责**：
- 封装 Agent API 调用
- 处理认证（Sa-Token JWT）
- 解析 SSE 流
- 错误处理

**关键函数**：
```typescript
// 流式对话
chatStream(content, onEvent, onError, options): ChatStreamHandle

// 获取历史会话
getSessions(): Promise<AgentSession[]>

// 删除会话
deleteSession(sessionId): Promise<void>

// 获取会话消息
getSessionMessages(sessionId): Promise<AgentHistoryMessage[]>

// L2 确认回调
confirmCard(payload): Promise<AgentConfirmData>
```

**B 端适配**：
```typescript
// 从 Sa-Token 获取 token
function authHeaders(): Record<string, string> {
  const token = localStorage.getItem('sphp_b_token') || '';
  return token ? { Authorization: `Bearer ${token}` } : {};
}
```

### 4.2 hooks/useAgentStream.ts

**职责**：
- 管理 SSE 连接状态
- 处理消息累积
- 管理会话 ID
- 提供发送、确认、取消等操作

**关键接口**：
```typescript
interface UseAgentStreamReturn {
  entries: AgentEntry[];           // 消息列表
  connection: ConnectionStatus;    // 连接状态
  errorMessage: string;            // 错误信息
  isStreaming: boolean;            // 是否正在流式传输
  send: (content, context?) => void;  // 发送消息
  confirm: (card) => void;         // 确认 L2 卡片
  cancel: () => void;              // 取消当前流
  reset: () => void;               // 重置会话
  loadSession: (sessionId) => void;  // 加载历史会话
}
```

**B 端适配**：
- localStorage 键名：`sphp_b_agent_session_id`

## 7. 错误处理

### 7.1 认证失败

**场景**：Sa-Token 过期或无效

**处理**：
- 响应状态码 401 时，跳转到 B 端登录页
- 提示"登录已失效，请重新登录"

### 7.2 网络错误

**场景**：网络连接失败、请求超时

**处理**：
- 网络连接失败：提示"网络连接失败，请稍后重试"
- 请求超时：提示"请求超时，请稍后重试"
- 服务端错误：提示"服务异常，请稍后重试"

### 7.3 流式中断

**场景**：用户中断、页面关闭、网络断开

**处理**：
- 用户点击"停止生成"：中断 SSE 流
- 页面关闭/刷新：自动中断连接
- 网络断开：检测并提示用户

### 7.4 会话管理

**场景**：会话不存在、会话过期

**处理**：
- 会话不存在：自动创建新会话
- 会话过期：提示用户并创建新会话

### 7.5 工具调用失败

**场景**：L2 确认失败、工具执行失败

**处理**：
- L2 确认失败：显示错误信息，允许重试
- 工具执行失败：显示错误卡片
- 超时处理：提示用户稍后重试

## 10. 风险与缓解

### 10.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| B 端认证方式与 C 端不同 | 认证失败 | 提前调研 Sa-Token 存储方式 |

### 10.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 医生不习惯使用 AI 助手 | 使用率低 | 提供使用引导和培训 |
| B 端功能不够丰富 | 价值不足 | 优先实现核心功能，逐步迭代 |
