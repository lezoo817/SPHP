## C 端 H5 —— Agent 对话上下文补全 address_id

按 D-1 周状核实要求，前端对话上下文传给 Agent 的 `address_id` 缺失——
Java 后端已提供 `/delivery-addresses` + `/pharmacies/recommendations`，
Agent 端 `recommend_pharmacies` 工具已支持 `address_id` 补全，仅前端
`context` 缺字段。

### 改动
- `src/typings/agent.ts` —— `AgentChatContext` 增加 `address_id?: number`
- `src/models/agent.ts` —— 保留同步 `buildAgentContext(pathname)`，新增：
  - `loadDefaultAddressId()`：异步调用 `getDeliveryAddresses()`，取 `isDefault` 项，无默认则取首条
  - `resolveAgentContext(pathname)`：基础 context + 异步补 `address_id`
- `src/pages/agent/index.tsx` —— 改用 `resolveAgentContext`（useState + useEffect），
  取消 cancelled 标志防止组件卸载后写状态

### 设计要点
- 同步 `buildAgentContext` 保留向后兼容（不依赖网络，含路由/选择类基础字段）
- 新增 `resolveAgentContext` 单独处理地址等异步 IO；接口失败仅缺 address_id，
  不影响其他字段，错误时优雅降级
- `getDeliveryAddresses` 注释已说明服务端默认地址优先返回，前端只需找 `isDefault`
