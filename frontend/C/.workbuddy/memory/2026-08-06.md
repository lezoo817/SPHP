## C 端 H5 —— 修复 L2 确认卡上方工具卡永久"调用中"

用户反馈：点击确认卡"提交"后，上方的 L2 工具卡（如"确认提交预问诊" /
`save_pre_consultation`）仍显示加载（"调用中"转圈）。

### 根因
后端 L2 工具（如 `save_pre_consultation`）在 `tool_caller` 推送 `action` 事件
（前端建 loading 工具卡），但 safety 把它移入 `pending_confirmations` 不执行，
**不下发 observation**。前端 `updateToolCard` 靠 observation 收尾，于是该卡
永久卡在 loading。

### 改动（仅 C 端前端 agent 模块，后端零改动）
1. `src/typings/agent.ts` —— `AgentToolCard.status` 增加 `'pending'`（待确认）
2. `src/constants/agent.ts` —— 新增 `AGENT_CARD_TYPE_TO_TOOL`
   （card_type → tool 反向映射，对齐后端 safety.py `_map_card_type`）
3. `src/hooks/useAgentStream.ts` —— 新增 `resolveL2ToolCard(cardType, patch)`：
   - 收到 `card` 事件时，把对应 L2 loading 工具卡收尾为 `pending`（summary "待您确认操作"）
   - `confirm()` 成功分支，把对应 L2 工具卡翻为 `success`（summary = 后端 message）
4. `src/components/agent/AgentToolCard.tsx` —— 渲染 `pending` → 扳手图标 + "待确认"
5. `src/styles/app.less` —— `.agent-tool--pending` 边框（amber，同 loading）+ 状态色 #b8860b

### 设计要点
- 匹配规则：card 事件 `card_type` → 反查 tool 名 → 找最近一张同 tool 且 loading 的工具卡
- 卡片到达即"待确认"（消除转圈误导），用户确认后翻"成功"，两阶段都自洽
- 失败分支不变（catch 仅更新卡片 error 态，不触碰工具卡）
- `confirm` 是 useCallback([])，resolveL2ToolCard 仅用稳定 setEntries + 常量，闭包安全
