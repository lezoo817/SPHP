# CLAUDE.md - 项目开发指南与 AI 协作规范

## ⚠️ 1. 绝对红线 (Absolute Rules - 最高优先级)

**在执行任何操作前，必须严格遵守以下两条红线，违反将导致严重事故：**

1. **禁止私自修改数据库**：任何涉及数据库表结构变更（DDL）或数据修改（DML）的操作，**必须先向用户报告并提供 SQL 脚本**，在获得用户明确批准后才可执行。**绝对禁止私自提交或执行数据库变更。**
2. **禁止私自 Git 提交**：**绝对禁止** AI 自动执行 `git add`, `git commit`, `git push` 等任何 Git 提交操作。所有代码变更必须由用户手动审查和提交。

## 2. 角色与项目上下文 (Context)

- **项目背景**：包含传统业务与 AI 智能助手的全栈项目。AI 模块（Python）由其他同事负责，不归本用户管理。
- **用户职责**：仅负责 **B端（医院管理后台）** 的前后端开发。
- **架构模式**：多模块/多仓库结构。AI 模块与传统业务模块同级；传统业务内部按 B/C 端及前后端拆分。
- **工作边界**：**严格限制在 B 端前后端范围内**。除非有特殊需求，**尽量不修改其他模块（如 C 端、AI 端）的代码**。不要假设存在可跨端复用的公共组件。

## 5. 编码规范与约定 (Coding Standards)

### 5.1 通用规范

- **代码注释**：关键业务逻辑、复杂算法、核心接口**必须**包含清晰的注释。
- **AI 交互风格**：**极简高效**。直接给出代码和关键结论，少说废话。
- **单元测试**：视情况而定。仅在用户明确要求时生成 JUnit + Mockito 测试用例。

### 5.2 后端规范 (Java)

- **基础规范**：严格参照 **《阿里巴巴 Java 开发手册》**。
  - **命名**：POJO 类布尔变量禁止加 `is` 前缀。
  - **并发**：优先利用 **Java 21 虚拟线程** 处理高并发 IO。
  - **日志**：必须使用 SLF4J 占位符 `{}`，**禁止字符串拼接**。
  - **SQL**：禁止 `select *`；MyBatis 必须用 `#{}` 防注入。
- **接口文档 (Apifox 适配)**：
  - 必须使用 `springdoc-openapi-starter-webmvc-ui`。
  - 注解使用 Swagger v3 (`io.swagger.v3.oas.annotations.*`)。
  - Controller 类用 `@Tag`，方法用 `@Operation`，字段用 `@Schema`。

## 6. 前端排查核心 SOP (Frontend Troubleshooting)

**当遇到前端 Bug 时，请严格按照以下步骤协助用户排查：**


| 步骤              | 核心操作                                            | 适用场景                    |
| :---------------- | :-------------------------------------------------- | :-------------------------- |
| **0. 环境确认**   | 强刷/无痕模式复现，核对环境与账号权限               | 所有问题首步                |
| **1. 代码生效**   | 加调试标识，检查 SourceMap 是否加载最新源码         | 修改无反馈、断点失效        |
| **2. 网络诊断**   | F12 查请求详情，核验 Mock 开关及代理/CORS 配置      | 白屏、数据异常、接口报错    |
| **3. 运行时追踪** | 用 DevTools 查状态/堆栈，console.log 兜底打印关键值 | JS 报错、渲染异常、死循环   |
| **4. 逻辑隔离**   | 将封装 Hook/组件降级为原生 API 验证                 | 封装库异常、复杂逻辑 Bug    |
| **5. 路由检查**   | 核对路由表、守卫鉴权及 URL 参数解析                 | 404、跳转死循环、刷新丢状态 |
| **6. 缓存清理**   | 删除`.umi/.cache` 等构建产物并重装依赖              | 代码无误但行为诡异          |
| **7. 外部因素** | 查浏览器兼容性、依赖 Changelog 及 Nginx/CDN 配置    | 特定浏览器报错、线上出错    |

## 7. Git 提交规范 (Commit Convention)

**注意：AI 严禁执行 git 命令，但生成的代码变更应遵循以下规范。**

- **格式**：`type(scope): subject`
- **Type**：`feat`(新功能), `fix`(修补bug), `docs`(文档), `refactor`(重构), `chore`(构建/工具)。
- **示例**：`feat(user): 新增用户列表查询接口及前端展示页面`

## 8. 跨模块交互 (Cross-Module Interaction)

- **与 AI 模块通信**：默认采用 **HTTP / RESTful API** (同步调用)。
- **接口定义**：优先定义好清晰的 Request/Response DTO。

## 9. 工作流 (Workflow)

1. **需求分析**：快速理解目标，若有歧义需简明确认。
2. **代码生成**：在 B 端边界内生成代码，添加注释和 OpenAPI 注解。
3. **数据库变更**：涉及 DDL/DML 时，**立即停止**，输出 SQL 脚本待审批。
4. **代码审查**：等待用户反馈并微调。
