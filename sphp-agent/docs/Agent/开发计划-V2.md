## 一、项目概述

**智愈先锋(SPHP) Agent 模块** — AI 驱动的全链路医疗健康平台的核心 AI 服务。

### 技术栈

FastAPI + LangGraph + MCP（Model Context Protocol）

### 四层架构

```
① API 接入层 (app/api/)         - 对话端点 + JWT 鉴权 + 限流
② 编排层 (app/orchestrator/)    - LangGraph 主图 + 子图 + 节点函数
③ 引擎层 (app/engine/)          - LLM 工厂 + 工具 Schema + RAG
④ MCP Server (app/mcp_server/)  - 工具封装（stdio transport）
⑤ 基础设施层 (app/infrastructure/) - Java 客户端 + Redis + 配置
```

### 核心机制

- **对话流程**: 前端 JWT → 鉴权 → 意图识别 → [业务操作/医疗咨询] → [工具调用/RAG] → 回复生成 → SSE 流式
- **L1-L4 安全**: L1 直接执行 / L2 生成 confirm_token 等待确认 / L3-L4 代码硬拦截不注册
- **SSE 事件**: `message`（LLM 输出）/ `action`（工具开始）/ `observation`（工具结果）/ `card`（L2 确认）/ `done`（完成）

### 核心边界

| 原则 | 含义 |
|------|------|
| 能查不能断 | 可查报告/药典，不可确诊、不可开方 |
| 能建议不能决定 | 可推荐医生/药品，不可替人挂号、替人下单 |
| 能代办不能代确认 | 可发起流程、创建草稿，但敏感操作必须人工确认 |

## 四、下一阶段（M2-M6）

### M2：工具调用可用 🔄 进行中

**目标**: LLM 能调工具查数据，action/observation 事件正确推送。

**1. 实现 `tool_caller` 节点**（0.5 天）
- 从 `ToolRegistry.get_openai_schemas(scope)` 获取工具 Schema
- 绑定工具到 LLM（`llm.bind_tools(tools)`）
- 构造工具选择 prompt，调用 LLM，解析 `tool_calls`
- 当前进度: 占位 `return {"tool_calls": []}`，依赖已就绪

**2. 主图接入工具链路**（0.5 天）
- 在 `main_graph` 注册 `tool_caller -> safety_check -> tool_executor`
- 修改 `route_by_intent`，让业务意图（triage/registration/consultation/pharmacy）路由到工具子图而非 `qa_node`
- 子图已编译（`build_tool_subgraph()`），可直接接入

**3. `tool_executor` 接入 MCP Client**（0.5 天，可选）
- 当前 Java REST 过渡实现可先跑通
- 后续替换为标准 MCP `tools/call`

**验收**: `curl 查科室 -> action 事件 -> observation 事件 -> 返回结果`

```bash

ZHIPU_API_KEY=your_key
PG_HOST=localhost
PG_PASSWORD=your_password      # 不再硬编码，必须配置
REDIS_HOST=localhost
```
